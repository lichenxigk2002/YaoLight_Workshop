# 自动化任务与触发器 PRD

## 1. 背景

当前平台的工作流执行入口以手动执行和开放 API 调用为主。数据库中已有 `task_schedules` 结构，开始节点默认配置也已出现 `manual / schedule / webhook` 触发类型提示，但缺少完整的调度器、Webhook 触发器、管理接口和前端配置页。

这意味着平台已经具备执行能力，却还没有真正形成“自动化巡航”。

## 2. 目标

- 支持工作流按 Cron 周期自动执行。
- 支持通过 Webhook 被外部系统触发。
- 支持查看待执行计划、历史触发记录、失败重试。
- 与现有任务、通知、artifact、开放 API 保持一致的审计与权限模型。

## 3. 非目标

- 本期不做复杂事件总线或多云调度。
- 本期不做 BPMN 级触发器编排。
- 本期不引入外部消息队列作为强依赖。

## 4. 用户场景

- 每天 8 点自动抓取一批站点并汇总成日报。
- 每周一自动执行知识库巡检与增量同步。
- 外部 CMS 在内容更新后通过 Webhook 触发工作流生成摘要与推送产物。

## 5. 产品范围

### 5.1 定时触发

- 支持 Cron 表达式
- 支持时区设置
- 支持启用/停用
- 支持生效时间范围

### 5.2 Webhook 触发

- 为工作流生成专属触发地址与签名密钥
- 接收 JSON 请求体作为开始节点输入
- 支持请求头签名校验、IP 白名单

### 5.3 计划任务管理

- 列表查看：待执行、最近执行、失败计划
- 单条取消、立即执行、批量取消
- 展示下一次执行时间与最近一次执行结果

## 6. 与现有模块集成

### 6.1 知识库

- 定时触发适用于知识库周期更新、网站源巡检、增量检索验证

### 6.2 爬虫规则

- 适用于定时抓取、轮询监控、价格/舆情巡航类工作流

### 6.3 生成物管理

- 每次自动执行生成的 artifact 需自动挂载到对应任务
- 支持配置“仅保留最近 N 次生成物”

## 7. 功能需求

### 7.1 调度配置

- 工作流详情页新增“自动化”页签
- 创建计划时填写：
  - 名称
  - Cron
  - 时区
  - 输入参数模板
  - 失败重试策略
  - 成功/失败通知

### 7.2 调度执行器

- 后端进程内启动调度 worker
- 周期扫描 `task_schedules`
- 对满足条件的计划创建新任务并触发工作流执行
- 同一时间点的同一计划只允许触发一次

### 7.3 Webhook 触发器

- 路由建议：
  - `POST /open-api/v1/triggers/:token/invoke`
- 支持：
  - `X-Trigger-Signature`
  - `X-Request-Id`
  - 重放保护

### 7.4 失败处理

- 支持重试策略：
  - 不重试
  - 固定次数重试
  - 指数退避

## 8. 自愈与异常处理

- 调度器重启后，应根据 `next_run_at` 自动恢复计划。
- 若某次触发失败，不能影响后续计划持续运行。
- 若同一计划因实例重启重复扫描，应依靠幂等锁避免重复创建任务。
- 若 Webhook 请求超时或签名不合法，应落审计日志并返回明确错误。

## 9. 数据模型建议

在现有 `task_schedules` 基础上补充或规范：
- `trigger_type = cron | webhook`
- `webhook_token`
- `webhook_secret_hash`
- `last_error_message`
- `retry_policy`
- `input_template`
- `last_trigger_request_id`

建议新增：
- `task_schedule_runs`

## 10. API 设计建议

用户侧：
- `GET /api/task-schedules`
- `POST /api/task-schedules`
- `PATCH /api/task-schedules/:id`
- `POST /api/task-schedules/:id/cancel`
- `POST /api/task-schedules/:id/trigger-now`

公开触发：
- `POST /open-api/v1/triggers/:token/invoke`

## 11. 前端需求

- 工作流页新增“自动化设置”
- 展示 Cron 人类可读预览
- 展示最近 10 次计划执行记录
- Webhook 模式支持复制地址、复制签名示例

## 12. 验收标准

- 用户可创建一个每天 8 点执行的计划，并在到点后自动生成任务。
- 调度器重启后，既有计划不会丢失。
- Webhook 触发可将请求体作为开始节点输入注入工作流。
- 失败重试、取消计划、立即执行三类操作均可闭环。

## 13. 优先级

- P0：Cron 调度 + 计划管理 + 幂等
- P1：Webhook 触发 + 签名
- P2：高级重试策略 + 运行配额
