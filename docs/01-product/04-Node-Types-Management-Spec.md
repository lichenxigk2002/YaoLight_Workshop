# 节点类型管理模块调整说明

## 背景

当前管理端“节点类型管理”页面已具备基础的列表、详情、新增、编辑、启停、删除能力，但业务边界还不够清晰。

现阶段平台中的大部分系统节点，其执行逻辑、前端画布表现、节点配置结构，实际上已经在代码中写死，不属于真正意义上的“动态节点插件系统”。因此，节点类型管理页不能简单按通用 CRUD 页面来处理。

这份文档用于明确后续调整方向，当前先记录规则，不作为本期必须开发项。

## 当前问题

1. 系统预设节点目前仍可进入编辑态，这和“执行逻辑已固化”的事实不一致。
2. “是否启用”与画布中的可添加性没有形成明确约束。
3. 自定义节点与系统节点的边界不清楚，容易让页面看起来像“都能编辑、都能动态生效”。
4. 该模块后续会接入权限控制，如果现在不先收口规则，权限点会设计错。

## 目标逻辑

### 1. 节点分层

节点类型分为两类：

- 系统预设节点
- 自定义节点

判定方式沿用当前数据模型中的 `is_system`。

### 2. 系统预设节点

系统预设节点的核心原则是：**只读为主，不允许修改业务定义。**

应遵循以下规则：

- 允许查看详情
- 不允许编辑名称、类别代码、描述、Schema、默认配置、示例配置等内容
- 不允许删除
- 允许控制启用 / 停用状态

推荐的页面行为：

- 列表中系统节点显示“系统预设”标签
- 点击后默认进入“查看详情”抽屉，而不是编辑表单
- 抽屉中的字段全部只读
- 页面不展示“删除”按钮
- 页面可保留“启用 / 停用”开关，作为唯一可操作项

说明：

系统节点的执行逻辑、前端节点组件、工作流编排约束、AI 能力说明等都和代码实现强绑定，因此不应在管理端开放编辑，否则会造成“配置可改，但运行并不会按配置变化”的假象。

### 3. 自定义节点

自定义节点的核心原则是：**允许新增，允许维护，但应和系统节点严格隔离。**

应遵循以下规则：

- 允许新增
- 允许查看详情
- 允许编辑
- 允许启用 / 停用
- 允许删除
- 类别代码必须唯一
- 不能与系统预设类别冲突

补充约束：

- 如果自定义节点已经被工作流引用，则不允许修改类别代码
- 如果自定义节点已经被工作流引用，则删除前必须先解除引用或阻止删除

## 启用状态与画布联动

节点类型的 `is_active` 不只是后台展示字段，应直接影响画布中的“可添加节点集合”。

目标规则如下：

- 节点类型为启用状态时，可以在工作流画布中被添加
- 节点类型为停用状态时，不应出现在画布右键菜单 / 节点面板 / 快速插入入口中
- 停用只影响“新增”，不强制删除历史工作流中已存在的节点实例

推荐解释：

- `启用` = 允许继续被用户新添加
- `停用` = 禁止新加，但保留历史兼容

这样做更稳，避免因为后台停用节点类型而直接破坏已有工作流。

## 画布侧消费规则

后续前端工作流编辑器应按“可见节点白名单”来渲染节点菜单，而不是写死全部节点都展示。

最低要求：

1. 右键新增节点菜单只展示 `is_active = true` 的节点类型
2. 节点面板只展示 `is_active = true` 的节点类型
3. 若历史工作流中存在已停用节点，画布仍应能正常渲染
4. 若节点已停用，用户不能再从菜单中新增同类型节点

## 与执行引擎的边界

这里要明确一个事实：

**“管理端新增了节点类型” 不等于 “平台已经支持这种节点的执行”。**

对于系统预设节点：

- 执行逻辑由后端工作流执行器决定
- 节点组件表现由前端编辑器决定
- AI 能力说明、节点说明文档也可能依赖代码内置定义

对于自定义节点：

- 如果后端没有对应执行逻辑，前端没有对应节点组件，就不能直接视为可运行节点
- 因此当前阶段更适合把“自定义节点”理解为预留能力，而不是完整插件系统

建议后续分两步走：

1. 先把“系统节点只读 + 启停影响画布可见性”做对
2. 再决定是否真正建设“自定义节点插件化”

## 管理端页面调整建议

### 列表页

- 增加“系统预设 / 自定义”标签
- 系统预设节点的主操作改为“查看”
- 自定义节点的主操作保留“编辑”
- 删除按钮仅对自定义节点显示
- 启用开关对两类节点都可保留

### 抽屉 / 详情页

系统预设节点：

- 只读详情模式
- 字段不可编辑
- 可展示节点说明、默认配置、Schema、示例配置
- 允许切换启用状态

自定义节点：

- 编辑模式
- 可修改名称、颜色、图标、描述、Schema、默认配置、示例配置
- 类别代码在已引用时锁定

## 与权限模块的衔接建议

因为你接下来要先做权限，这里建议直接按下面的权限粒度设计：

- `node_types.view`：查看节点类型列表与详情
- `node_types.create`：新增自定义节点
- `node_types.update_custom`：编辑自定义节点
- `node_types.toggle_status`：启用 / 停用节点类型
- `node_types.delete_custom`：删除自定义节点

系统节点不建议提供 `update_system` 权限，因为业务上就不应开放。

## 本期不做的内容

这次先不做以下能力：

- 真正的动态节点插件系统
- 自定义节点自动生成前端画布组件
- 自定义节点自动接入后端执行引擎
- 节点版本管理
- 节点上线审批流

## 验收口径

后续如果按这份文档实现，至少应满足以下结果：

1. 系统预设节点只能查看，不能编辑、不能删除
2. 自定义节点可以新增、编辑、启停、删除
3. 节点停用后，不再出现在画布新增菜单中
4. 已存在于历史工作流中的节点，不因停用而直接失效
5. 权限系统能按“查看 / 新增 / 编辑自定义 / 启停 / 删除自定义”进行控制
