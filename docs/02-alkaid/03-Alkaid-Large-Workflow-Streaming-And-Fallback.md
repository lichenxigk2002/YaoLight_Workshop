# 瑶光星大工作流输出兜底说明

## 目标

解决两类体验问题：

1. 前端在长时间规划/生成时只有转圈，没有可见反馈。
2. 模型在生成“大工作流 + 长解释”时，容易因为输出过长导致 JSON 被截断，最终拿不到 `pending_workflow`。

## 本轮改动

代码位置：
- `backend/modules/alkaid/services/agentic/loop.go`

新增能力：
- 在工具检索完成、准备进入较长生成阶段时，先推送一条可见提示，减少“卡死感”。
- 当首轮回复没有成功提取出完整工作流 JSON，但已经出现明显的工作流结构信号时，自动触发第二轮紧凑生成。
- 第二轮生成只要求输出完整工作流 JSON，不再混合长解释文本。
- 第二轮生成会使用更保守的结构化参数：
  - `temperature = 0.2`
  - `maxTokens = 8000`

## 触发条件

满足其一即可进入第二轮兜底：

- 助手回复里出现 `<!-- workflow-json -->`、`"nodes"`、`"edges"`、典型节点类型等结构化信号。
- 用户问题本身明确在要工作流，且首轮回复已经很长，但仍未提取出合法工作流 JSON。

## 第二轮生成策略

第二轮不会重新让模型写一大段说明，而是要求：

- 只输出 JSON 对象
- 不输出 Markdown、代码块、标题、解释
- 必须包含 `version`、`name`、`description`、`nodes`、`edges`
- 优先压缩长文案，而不是破坏结构完整性
- 如果内容仍然偏长，优先保留关键节点、关键连线和可运行配置

## 预期效果

- 首轮“解释 + 大 JSON”被截断时，不再直接失败退出。
- 后端会尽量继续整理出一个可校验、可试跑、可提议的工作流。
- 用户更容易看到 `pending_workflow` 卡片，而不是只得到一条半截文本。

## 仍然存在的边界

- 这不是绝对保证。若模型第二轮仍然超长、偏题或返回非法 JSON，系统仍可能只能保留文本方案。
- 当前前端收到的状态提示属于流式内容提示，不一定会和最终持久化消息完全一致。
- 如果后续要进一步提升稳定性，建议再做：
  - 工作流 JSON 专用输出模板
  - 节点文案自动压缩
  - 超长工作流分段生成/拼装
