# 嵌套工作流与插件化 PRD

## 1. 背景

当前平台已支持工作流模板、节点配置、变量传递、工作流公开 API、AI 助手生成工作流，但仍缺少“把一个完整工作流封装为节点”的能力。  
这导致复杂流程只能铺在一个大画布上，复用、共享、维护和多智能体协作成本较高。

现有代码现状：
- 有工作流模板能力，但模板仍是“复制画布”，不是“节点级复用”。
- 开始节点已具备双模态雏形：既可读取节点内手工输入，也可读取运行时 `RuntimeInput`。
- 当前节点类型中没有 `subworkflow` / `plugin` 节点。

## 2. 目标

- 新增“子工作流节点”，允许将一个工作流封装为可复用插件。
- 支持输入映射、输出映射、版本控制、递归调用保护。
- 让用户能构建“主工作流编排 + 子工作流执行”的多层结构。
- 为后续多智能体协作、官方插件市场、团队复用打基础。

## 3. 非目标

- 本期不做完整插件市场商业化能力。
- 本期不支持无限深度递归执行。
- 本期不开放任意用户调用他人私有工作流，权限仍遵循当前项目/用户访问规则。

## 4. 核心概念

### 4.1 子工作流节点

- 新节点类型：`subworkflow`
- 节点本质：执行一个被引用的工作流，并把其结果返回给主画布

### 4.2 插件版本

- 每个可封装工作流可发布为插件版本
- 主工作流引用时可选择：
  - 跟随最新版
  - 固定版本

### 4.3 输入/输出映射

- 主工作流上游数据映射到子工作流开始节点输入
- 子工作流结束结果映射回当前节点输出

## 5. 开始节点双模态设计

这是本能力的关键。

开始节点需要支持两种模式：

### 5.1 独立运行模式

- 用户直接打开子工作流单独测试
- 开始节点使用当前节点配置中的手工输入
- 用于开发、调试、模板预览

### 5.2 插件运行模式

- 子工作流被 `subworkflow` 节点调用
- 开始节点优先读取主工作流传入的 runtime input
- 未传入字段可回退到默认值

### 5.3 模式切换规则

- 若存在 `RuntimeInput`，优先使用注入输入
- 若不存在，则使用开始节点内配置输入
- 支持字段级 merge，而不是只能整包覆盖

## 6. 功能需求

### 6.1 工作流封装

- 用户可在工作流详情页将当前工作流标记为“可封装为插件”
- 可填写插件名称、描述、输入说明、输出说明、版本说明

### 6.2 子工作流节点配置

- 选择目标工作流 / 插件版本
- 配置输入映射：
  - 常量值
  - 变量引用
  - 表达式
- 配置输出映射：
  - 直接返回子工作流最终结果
  - 仅返回指定字段

### 6.3 运行时行为

- `subworkflow` 节点执行时启动一个子执行上下文
- 子执行上下文继承：
  - 用户身份
  - 项目上下文
  - 请求链路 ID
  - 调用深度计数

### 6.4 递归保护

- 禁止直接自调用
- 限制最大调用深度，建议默认 `3`
- 检测循环依赖链：A -> B -> C -> A

## 7. 与现有模块集成

### 7.1 知识库

- 子工作流应继承或显式选择项目知识库作用域
- 知识检索节点要知道当前运行在主工作流还是子工作流上下文

### 7.2 爬虫规则

- 子工作流可复用既有爬虫规则配置
- 若子工作流依赖敏感爬虫配置，需配合凭证中心能力一起治理

### 7.3 生成物管理

- 子工作流生成的 artifact 可选择：
  - 挂到子任务
  - 回传到主任务
  - 两者都保留

## 8. 异常处理与自愈

- 子工作流失败时，`subworkflow` 节点视为失败节点
- 提供三种失败策略：
  - 终止主流程
  - 返回默认输出继续
  - 重试子工作流后再判定

- 子工作流超时、取消、权限失败时，要返回结构化错误，不允许只回字符串

## 9. 数据模型建议

建议新增：
- `workflow_plugins`
- `workflow_plugin_versions`
- `workflow_node_subworkflow_refs`

节点配置建议新增字段：
- `workflowId`
- `pluginVersion`
- `inputMapping`
- `outputMapping`
- `failurePolicy`

## 10. 前端需求

- 画布新增“子工作流节点”
- 节点配置面板支持插件选择、输入输出映射配置
- 插件详情页支持版本列表、示例输入、示例输出

## 11. 验收标准

- 用户可将一个工作流封装为插件，并在另一工作流中作为节点调用
- 开始节点在“独立运行 / 上游注入”两种模式下行为正确
- 子工作流的输出可稳定回传给主工作流下游节点
- 存在递归依赖时，保存或执行阶段能给出明确报错

## 12. 里程碑

- M1：`subworkflow` 节点模型与后端执行原型
- M2：输入输出映射 + 开始节点双模态完善
- M3：插件版本与前端配置页
- M4：递归保护、artifact 归集、灰度发布
