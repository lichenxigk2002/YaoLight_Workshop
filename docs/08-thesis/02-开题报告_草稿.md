# 毕业设计开题报告

## 1. 综述本课题国内外研究动态，说明选题的依据和意义

### 1.1 国内外研究动态

随着企业数字化转型加速，软件开发模式正向高效、灵活方向演进。低代码/零代码平台通过可视化手段降低了应用构建门槛，而大语言模型（LLM）的爆发则为软件智能化带来了新机遇。

**国内研究现状**：
国内低代码市场发展迅速，**王伟等（2023）** 在《软件学报》的综述中指出，低代码平台已成为提升研发效率的关键技术[1]。**艾瑞咨询（2024）** 的报告显示，中国低代码市场规模持续增长[2]。目前主流平台呈现出不同侧重：钉钉宜搭、腾讯微搭主要面向表单驱动的审批流与轻量级企业应用；**Coze（扣子）**、**Dify** 等新兴平台则聚焦于LLM智能体（Agent）的构建与知识库编排，极大地推动了AI应用的普及。然而，这些平台大多是闭源商业产品（Coze），或更侧重于**以大模型为核心的应用开发（LLM App Builder）**（Dify），对于需要深度自定义后端逻辑、集成复杂网络爬虫（如绕过反爬、动态渲染）及私有化部署的“端到端”数据处理工作流，仍缺乏足够的灵活性与开源解决方案。

**国外研究现状**：
国际上，**Al-Omari等（2021）** 调查了影响低代码平台采纳的因素，发现易用性与功能扩展性是关键[6]。在自动化领域，**n8n** 作为开源工作流自动化的标杆，通过节点编排实现了强大的服务集成能力；Zapier、Make等iPaaS平台生态成熟，但在私有化部署上受限。**Wang L等（2024）** 在LLM Agent综述中提出了基于大模型的自主智能体架构[8]，这为“AI生成工作流”提供了理论基础。

综上所述，虽然低代码与工作流技术已相对成熟，但将“可视化编排”、“LLM智能生成”与“通用网络爬虫”深度融合的研究仍较少。现有平台要么缺乏AI生成的灵活性，要么缺乏对复杂数据采集与处理的内置支持。

### 1.2 选题的依据和意义

**选题依据**：
本选题依据当前软件工程领域“智能化”与“自动化”的发展趋势。一方面，传统手工编写爬虫与数据处理脚本成本高、维护难；另一方面，普通用户难以直接利用LLM的API构建复杂应用。基于React与Go技术栈构建一个融合AI助手与可视化编排的平台，能够有效解决上述痛点。

**选题意义**：
1.  **理论价值**：本课题将探索LLM与可视化工作流的融合模式，验证基于自然语言生成结构化工作流（Text-to-Workflow）的可行性，为AI辅助软件工程（AI4SE）提供实证案例。
2.  **实际应用前景**：项目成果“瑶光工坊”可广泛应用于舆情监控、竞品分析、内容自动化生成等场景。通过“瑶光星”AI助手，用户只需一句话即可生成包含爬虫、分析、输出的完整流程，极大地降低了技术门槛，提高了业务自动化效率。

## 2. 研究的基本内容，拟解决的主要问题

### 2.1 研究的基本内容

本课题旨在设计并实现一个基于Go与React的低代码智能工作流平台“瑶光工坊”。主要研究内容包括：

1.  **可视化工作流编辑器设计**：基于 **React 19** 与 **React Flow** 实现高性能拖拽式画布，集成 **Ant Design** 与 **LobeHub UI** 构建现代化交互界面。支持节点（Node）与连线（Edge）的智能吸附与验证，开发包括 **AI模型调用、Headless爬虫、数据清洗、格式转换、逻辑判断（If/Else）、循环控制（Loop）** 等多种功能节点，并提供实时属性配置面板与执行状态反馈。
2.  **高性能工作流执行引擎**：基于 **Go** 语言实现后端核心执行器，采用 **DAG（有向无环图）** 拓扑排序算法解析流程。支持 **流式响应（Streaming）**、节点并发执行、上下文变量传递（Context Propagation）及细粒度的错误处理机制。内置 **数据清洗（DataClean）** 模块，支持通过正则表达式与自定义规则对采集数据进行标准化处理。
3.  **瑶光星（Alkaid）AI助手**：设计 **Agentic（代理）** 架构，实现“用户指令 -> 意图识别 -> 结构化工作流生成”的自动化链路。采用 **多轮决策（Multi-turn Decision Making）** 机制替代传统的单次生成模式，支持 **全链路可观测性（Observability）**，用户可实时查看 Agent 的规划、工具调用及执行进度。引入 **人机协同（Human-in-the-Loop）** 交互模型，对“应用补丁”、“写回画布”等关键操作引入人工确认机制，确保系统安全可控。同时利用 **Rule-based RAG** 技术动态注入节点规格，结合“生成-校验-修复”闭环机制确保逻辑正确性。
4.  **多模态AI与爬虫集成**：设计统一的 **Model Provider** 适配层，全面接入 **DeepSeek、OpenAI (GPT)、Claude、Gemini、腾讯混元、字节豆包、阿里通义千问 (Qwen)、讯飞星火、Moonshot (Kimi)、Grok** 等主流大模型接口。集成 **ChromeDP** 实现无头浏览器爬虫，支持动态页面渲染、截图、HTML解析及反爬虫策略对抗。
5.  **系统管理与增值服务**：实现基于 **JWT** 的用户认证与权限管理。构建 **可插拔钩子（Pluggable Hooks）** 系统，在工作流生成或执行的关键节点支持策略注入（如风控、合规检查）。构建 **Stardust 计费系统**，支持基于Token消耗的模型定价与订单管理。提供丰富的 **结果导出** 功能，支持将运行结果导出为 PDF、Word、Mermaid 图表、Sankey 桑基图等多种格式。

### 2.2 拟解决的主要问题

1.  **工作流生成的准确性与可执行性**：LLM生成的JSON结构可能存在幻觉或逻辑错误（如参数缺失、连线闭环）。拟采用 **结构化知识库（Structured Knowledge Base）** 与 **JSON Schema** 双重约束。在生成阶段，通过 **Prompt Engineering** 注入节点元数据与约束条件；在后处理阶段，利用 **AST 解析** 与 **拓扑校验** 工具自动识别逻辑漏洞，并反馈给 LLM 进行 **自我修正（Self-Correction）**。
2.  **复杂流程的调度与状态管理**：在支持循环、分支及长运行任务（如大模型生成）时，如何保持引擎的稳定性与状态一致性。拟采用基于 **Context** 的变量作用域管理机制与基于 **Goroutine** 的并发调度算法，结合 **Redis** 进行运行时状态持久化。
3.  **异构数据的流转与清洗**：不同节点（如爬虫输出的HTML与LLM需要的Text）之间的数据格式差异。拟设计标准化的 **Transform（转换）** 节点与 **DataClean（清洗）** 服务，支持 JSONPath 提取与模板渲染，实现数据在节点间的无缝流转。
4.  **多源模型与反爬策略的兼容性**：如何屏蔽不同大模型API的差异，以及应对网页反爬机制。拟设计统一的 **Provider Interface** 接口屏蔽底层差异，并在爬虫节点内置 **User-Agent 池**、**延时策略** 及 **Cookie 管理** 功能。

## 3. 研究步骤、方法及措施

### 3.1 研究步骤

本课题的研究将遵循软件工程的标准生命周期，分为以下几个阶段有序进行：

1.  **准备与调研阶段**：查阅国内外关于低代码平台、Agentic Workflow 及爬虫技术的相关文献，明确研究方向；分析现有竞品（如 Dify、n8n）的优缺点，完成需求调研与开题报告撰写。
2.  **系统分析与设计阶段**：进行详细的需求分析，确定系统的功能模块与非功能性需求。设计系统总体架构、数据库模型（ER图）、API 接口定义及工作流 JSON 规范（DSL）。
3.  **核心功能开发阶段**：
    *   **前端开发**：基于 React Flow 搭建可视化编辑器，实现节点的拖拽、配置与连线交互。
    *   **后端开发**：构建基于 Go 的工作流执行引擎，实现 DAG 拓扑排序、节点调度与并发执行逻辑。
4.  **AI 增强与高级特性开发阶段**：研发瑶光星（Alkaid）AI 助手，实现 Prompt 工程与 RAG 知识库检索；开发 Config Extractor 以保证知识与代码的一致性；集成多模型 Provider 与 Headless 爬虫节点。
5.  **系统测试与优化阶段**：开展单元测试与集成测试，验证工作流生成的准确性与执行引擎的稳定性。根据测试结果进行性能调优（如 Goroutine 调度优化）与 UI/UX 改进。
6.  **论文撰写与总结阶段**：整理设计文档、测试数据与实验结果，撰写毕业论文，并准备答辩演示材料。

### 3.2 方法及措施

1.  **文献研究法**：通过CNKI、IEEE Xplore、GitHub等渠道收集低代码、Agent、爬虫相关的最新资料，构建扎实的理论基础。
2.  **原型迭代法**：采用敏捷开发模式，先构建MVP（最小可行性产品）验证核心链路（如“画一个节点 -> 执行成功”），再逐步迭代AI生成与复杂节点功能。
3.  **技术实现措施**：
    *   **前端**：使用 **React 19 + TypeScript + Vite** 构建高性能应用，采用 **React Flow** 实现可视化编排，**Zustand** 进行全局状态管理，结合 **Ant Design** 与 **LobeHub UI** 打造现代化界面。
    *   **后端**：使用 **Go (Golang) + Gin** 框架，利用 Goroutine 高并发特性支撑工作流引擎。开发 **Config Extractor（配置抽取器）**，基于 **AST（抽象语法树）** 自动从 Go 源码提取节点规格（Node Specs），确保 AI 知识库与后端代码实现的严格一致，根除因文档滞后导致的幻觉问题。
    *   **数据存储**：**PostgreSQL** 存储用户、工作流及订单数据，**Redis** 缓存 OAuth Token 及运行时状态。
    *   **AI集成**：设计 **Provider Factory** 模式，通过统一接口适配 **DeepSeek、OpenAI** 等多源模型，支持流式传输（SSE）。
4.  **工程化保障**：使用Git进行版本控制，编写单元测试（Unit Test）验证核心算法，利用 **Docker Compose** 进行环境编排，并配置 **GitHub Actions** 实现 **CI/CD（持续集成与持续部署）** 自动化流程。

## 4. 研究工作进度

*   **第1周**：查阅、收集相关资料，撰写开题报告。
*   **第2-3周**：系统的需求分析与设计，技术准备，完成需求分析报告和系统设计报告。

*   **第10-11周**：程序代码测试与改进，进行系统全面测试，根据测试结果优化系统。同时，开始撰写毕业论文。
*   **第12-13周**：修改、提交毕业论文，完善系统文档。
*   **第14周**：毕业论文答辩。

## 6. 答辩内容

### 6.1 预期成果

1.  **系统成果**：完成基于 **React Flow** 与 **Go** 的低代码智能工作流平台“瑶光工坊”。系统具备 **Agentic Workflow 生成**、**可视化编排**、**多模型集成**、**Headless 爬虫执行** 及 **数据清洗导出** 等核心功能，支持 **Docker 一键部署**。
2.  **学术成果**：撰写不少于 1.5 万字的毕业论文，详细阐述系统的设计思路、关键技术（如 RAG、AST 配置抽取、Goroutine 并发调度）及测试结果，格式符合学校规范。
3.  **文档成果**：提供完整的软件工程文档，包括《需求规格说明书》、《系统设计说明书》、《API 接口文档》及《测试报告》。

### 6.2 答辩演示规划

在毕业答辩环节，拟重点展示以下内容：

1.  **PPT 汇报**：
    *   **选题背景与意义**：阐述低代码与 LLM Agent 结合的必然性及市场价值。
    *   **技术架构与创新点**：重点汇报 **Rule-based RAG 知识库**、**AST 配置抽取** 及 **Agentic Loop 自我修正机制** 等技术难点。
    *   **系统实现与测试**：展示系统核心模块的实现逻辑及性能测试数据。
2.  **系统现场演示**：
    *   **全流程闭环**：演示“用户输入自然语言需求（如‘爬取某网站新闻’） -> AI 自动生成工作流 -> 可视化修改参数 -> 运行爬虫任务 -> 导出 Excel”的完整业务流程。
    *   **核心特性展示**：展示 **瑶光星 AI 助手** 的多轮对话能力、**流式日志反馈** 及 **断点续传/重试** 机制。
