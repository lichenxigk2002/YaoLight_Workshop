# 统一凭证中心 PRD

## 1. 背景

当前项目已经具备部分敏感信息处理能力：
- AI 模型支持 API Key 加密存储
- 爬虫节点/爬虫规则支持 headers、cookies
- 部分日志中已有敏感字段脱敏意识

但这些能力仍然分散在不同模块中，缺少统一的凭证中心。  
结果是：敏感值容易散落在节点配置里，工作流难以安全分享，也无法实现环境隔离和统一轮换。

## 2. 目标

- 新增统一凭证中心，集中管理 API Key、Cookie、数据库连接串、Webhook Secret 等敏感信息。
- 工作流节点通过变量引用凭证，而非直接保存明文。
- 支持环境隔离：开发、测试、生产可绑定不同凭证值。
- 提供权限、审计、轮换、失效控制能力。

## 3. 非目标

- 本期不接入外部企业级 Secret Manager。
- 本期不做 KMS/HSM 深度集成。
- 本期不开放给任意脚本执行系统级 shell secret 注入。

## 4. 用户价值

- 工作流分享与模板复用更安全。
- 团队能统一维护第三方服务账号，不必逐节点修改。
- 事故排查时能知道谁何时修改了哪个凭证。

## 5. 产品范围

### 5.1 凭证类型

- API Key
- HTTP Header 凭证
- Cookie 组
- Bearer Token
- 数据库连接
- 自定义键值集合

### 5.2 引用方式

- 节点配置中使用变量引用：
  - `{{secrets.OPENAI_API_KEY}}`
  - `{{secrets.CRAWLER_COOKIE_SET}}`

### 5.3 环境隔离

- 一个逻辑凭证可绑定多个环境值：
  - dev
  - staging
  - prod

## 6. 功能需求

### 6.1 凭证管理后台

- 创建凭证
- 查看元信息
- 更新值
- 启用/停用
- 轮换历史
- 查看引用该凭证的工作流

### 6.2 执行期注入

- 工作流保存时只保存引用名，不保存明文
- 执行前由后端解析引用并注入到运行时配置
- 前端只展示脱敏摘要，不回显真实值

### 6.3 权限与审计

- 普通用户只能管理自己的凭证
- 管理员可查看元信息，不默认查看明文
- 所有新增、修改、轮换、删除行为写入审计日志

## 7. 与现有模块集成

### 7.1 AI 模型

- 当前“已保存模型 API Key”能力可逐步迁移到凭证中心
- 模型配置改为引用凭证 ID 或凭证别名

### 7.2 爬虫规则

- headers/cookies/proxy 配置可引用凭证，而不是直接写在规则中

### 7.3 开放 API 与 Webhook

- API Key、Webhook Secret 可统一纳入凭证中心管理和轮换

## 8. 安全设计

- 数据库存储使用现有加密能力扩展，不允许明文落库
- 日志、SSE、错误栈、AI prompt 中不得出现明文凭证
- 支持“值不可见”模式：创建后不再回显

## 9. 自愈与异常处理

- 若凭证缺失，节点执行失败时返回结构化错误：
  - 凭证不存在
  - 凭证已停用
  - 当前环境未配置值

- 若轮换后新值失效，允许一键回滚到上一个版本

## 10. 数据模型建议

建议新增：
- `credentials`
- `credential_versions`
- `credential_bindings`

核心字段：
- `name`
- `type`
- `scope`
- `environment`
- `encrypted_value`
- `status`
- `last_rotated_at`

## 11. API 设计建议

- `GET /api/credentials`
- `POST /api/credentials`
- `PATCH /api/credentials/:id`
- `POST /api/credentials/:id/rotate`
- `GET /api/credentials/:id/usages`

## 12. 前端需求

- 设置页新增“凭证中心”
- 节点配置表单支持“直接输入 / 引用凭证”切换
- 对已引用凭证展示名称、环境、最后更新时间

## 13. 验收标准

- 用户可创建一个 API Key 凭证，并在 AI 节点中通过变量引用使用
- 工作流 JSON 导出时不包含凭证明文
- 执行日志、错误日志、AI prompt 中不泄漏敏感值
- 同一工作流在不同环境中可切换到不同凭证值

## 14. 优先级

- P0：凭证实体、加密存储、节点引用
- P1：环境隔离、审计日志、引用分析
- P2：轮换策略、批量替换、风险扫描
