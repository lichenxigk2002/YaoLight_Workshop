# 第1章 绪论

## 1.1 课题背景

随着企业数字化转型与业务流程自动化需求日益增长，传统软件开发模式面临开发周期长、维护成本高、业务迭代慢等挑战。低代码/零代码平台通过可视化拖拽与配置化开发，显著降低应用构建门槛，成为提升研发效率的重要方向[1]。与此同时，数据采集、AI分析与内容生成等应用场景日趋丰富，用户往往需要串联网页抓取、数据清洗、大模型调用、结果输出等多个环节，手工编排成本高且易出错[2]。工作流技术能够将复杂流程拆解为可复用的节点与连线，通过拓扑排序与并发执行实现流程自动化；而大语言模型（Large Language Model, LLM）的快速发展，使得通过自然语言生成可执行工作流成为可能，进一步降低用户使用门槛[3]。在此背景下，设计并实现一个融合可视化编辑、智能工作流生成、多AI模型接入与爬虫采集能力的低代码智能工作流平台，对于探索低代码与AI的结合、推动数据与业务流程的自动化具有重要的实践意义。

## 1.2 国内外研究现状

### 1.2.1 低代码与工作流平台发展现状

国内方面，钉钉宜搭、腾讯微搭、字节飞书多维表格等低代码平台已在企业场景中推广，主要面向表单、审批等轻量级应用构建[4]。开源领域，N8n、Node-RED等支持节点式工作流编排，但多侧重自动化与物联网场景，与数据采集、AI分析的一体化整合不足。国外方面，Zapier、Make（原Integromat）在集成与自动化方向较为成熟；Temporal、Airflow等则面向复杂工作流编排与调度，偏向工程化与运维侧[5]。相关研究指出，将可视化编排与执行引擎解耦、支持可扩展节点类型、具备良好的变量引用与数据流管理，是提升工作流平台通用性与易用性的关键[6]。然而，针对"低代码+工作流+AI+爬虫"一体化平台的设计与实现研究仍较为分散，系统性的技术方案与工程实践文档相对有限。

### 1.2.2 AI辅助工作流生成技术

大语言模型在代码生成、任务规划等领域的应用已较为成熟。近年来的研究开始探索将LLM用于工作流生成：通过自然语言描述目标，由模型输出结构化工作流定义或执行计划[7]。相关工作涉及Prompt设计、结构化输出约束、RAG（检索增强生成）注入领域知识等[8]。现有研究多聚焦于单一工具链或简单流程，对于多节点类型、复杂数据依赖、变量引用与校验闭环的研究有待深入。将LLM与工作流执行引擎结合，实现"生成—校验—修复"的闭环，是提升生成可用性的重要方向[9]。

### 1.2.3 前后端分离架构与相关技术实践

前后端分离已成为Web应用的主流架构。后端采用Go、Node.js等高并发语言，配合Gin、Express等框架；前端采用React、Vue等框架，结合React Flow、Vue Flow等图编辑库实现可视化编排，已在大量项目中得到验证[10]。相关实践表明，清晰的数据模型、规范的RESTful API与WebSocket实时推送，对工作流编辑与任务监控的用户体验至关重要[11]。将前后端分离架构应用于低代码工作流平台，并与AI能力、爬虫能力相结合，是技术可行性与应用价值兼具的研究方向。

## 1.3 课题目的与意义

### 1.3.1 课题目的

本研究旨在设计并实现一个基于Go与React的低代码智能工作流平台（瑶光工坊），具体目的包括：（1）分析低代码工作流平台的功能与非功能需求，明确用户管理、工作流编辑、任务执行、AI辅助生成等核心模块；（2）设计包含开始、爬虫、AI处理、数据清洗、条件分支、数据转换、循环、合并、输出、结束等在内的多种节点类型及数据流规范；（3）实现基于拓扑排序的工作流执行引擎，支持并发执行、条件分支与循环处理；（4）设计并实现瑶光星（Alkaid）AI助手，采用Agentic工具调用架构，通过自然语言对话生成可导入、可执行的工作流，并实现校验—试跑—修复闭环与补丁机制；（5）集成多AI模型与爬虫能力，支持网页抓取、数据清洗与AI分析的端到端流程；（6）通过前后端集成与部署，形成可实际运行的系统原型，并进行功能与性能测试，验证系统的可靠性、可扩展性与用户体验。

### 1.3.2 课题意义

本课题的理论意义在于，系统梳理低代码、工作流、LLM辅助生成等相关理论与技术基础，探索可视化工作流编辑与AI生成相结合的设计与实现方法，为同类平台的开发提供参考。其实践意义在于，为数据采集、AI分析与内容生成等场景提供便捷、可扩展的一体化平台，同时通过完整的系统设计与开发过程，深化对前后端架构、工作流引擎、AI集成及用户体验设计的理解，有效提升在软件工程领域的综合实践能力与创新素质[12]。

本课题的创新点之一在于将大语言模型与可视化工作流平台深度融合，设计并实现瑶光星（Alkaid）AI助手：采用Agentic工具调用架构，使AI能够按需获取能力规范、知识库与当前画布上下文；引入校验—试跑—修复闭环，在工作流试跑失败时自动构造修复提示并重新生成，显著提高一次跑通率；设计补丁机制，支持对已有工作流的增量式修改，并结合Human-in-the-Loop确保用户对画布的最终控制权。上述设计有效降低了工作流搭建门槛，提升了平台的易用性与可信度。

## 1.4 主要工作内容与技术路线

本研究的主要工作内容包括：

（1）**需求分析与总体设计**：明确系统功能模块、数据模型、API规范及前后端职责划分；

（2）**基于React与React Flow的前端设计与实现**：完成工作流编辑器、节点配置面板、任务监控及瑶光星AI助手等组件的开发；

（3）**基于Go与Gin的后端服务设计与实现**：完成用户认证、工作流管理、任务调度、执行引擎及AI服务等核心接口；

（4）**工作流执行引擎实现**：包括拓扑排序、节点依赖解析、变量上下文与模板解析、条件分支与循环控制逻辑；

（5）**瑶光星AI助手实现**：包括Agentic工具调用、能力服务与Prompt构建、知识库检索与RAG增强、校验—试跑—修复闭环及补丁机制；

（6）**爬虫与多AI模型集成**：实现基于ChromeDP的网页抓取及多模型提供商的统一接入；

（7）**系统功能与性能测试**：验证核心功能的正确性、稳定性及用户体验。

技术路线为：首先梳理低代码、工作流及AI辅助生成的理论与技术基础；在此基础上进行需求分析与总体设计；进而完成前端界面、后端服务、执行引擎及瑶光星AI助手的详细设计与编码实现；最后对系统进行测试与验证，形成完整的设计与实现成果。论文章节安排如下：第二章介绍相关理论与技术基础；第三章阐述系统需求分析与总体设计；第四章描述系统详细设计与实现；第五章进行系统测试与验证；第六章总结全文并展望后续工作。
