# 瑶光工坊 (YaoLight Workshop) 数据库设计文档

## 一、数据库概述

- **数据库名称**: yaolight_workshop_db
- **数据库类型**: PostgreSQL 14+
- **字符集**: UTF8
- **迁移方式**: GORM AutoMigrate（启动时自动执行）

## 二、数据表设计

### 2.1 用户表 (users)

```sql
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE NOT NULL,
    password VARCHAR(255) NOT NULL,
    role VARCHAR(20) NOT NULL DEFAULT 'user' CHECK (role IN ('admin', 'user')),
    status VARCHAR(20) NOT NULL DEFAULT 'active' CHECK (status IN ('active', 'inactive')),
    avatar_url VARCHAR(255),
    last_login_at TIMESTAMP,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_users_username ON users(username);
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_role ON users(role);
CREATE INDEX idx_users_status ON users(status);
```

**字段说明**:
- `id`: 主键，自增
- `username`: 用户名，唯一，最大50字符
- `email`: 邮箱，唯一，最大100字符
- `password`: 密码（bcrypt加密后）
- `role`: 角色（admin/user）
- `status`: 状态（active/inactive）
- `avatar_url`: 头像URL
- `last_login_at`: 最后登录时间
- `created_at`: 创建时间
- `updated_at`: 更新时间

### 2.2 工作流表 (workflows)

```sql
CREATE TABLE workflows (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name VARCHAR(200) NOT NULL,
    description TEXT,
    version VARCHAR(20) NOT NULL DEFAULT '1.0.0',
    status VARCHAR(20) NOT NULL DEFAULT 'draft' CHECK (status IN ('draft', 'published', 'archived')),
    config JSONB NOT NULL DEFAULT '{}',
    is_template BOOLEAN NOT NULL DEFAULT FALSE,
    template_id BIGINT REFERENCES workflows(id) ON DELETE SET NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_workflows_user_id ON workflows(user_id);
CREATE INDEX idx_workflows_status ON workflows(status);
CREATE INDEX idx_workflows_is_template ON workflows(is_template);
CREATE INDEX idx_workflows_created_at ON workflows(created_at);
CREATE INDEX idx_workflows_config ON workflows USING GIN(config);
```

**字段说明**:
- `id`: 主键
- `user_id`: 创建者ID（外键）
- `name`: 工作流名称
- `description`: 描述
- `version`: 版本号
- `status`: 状态（draft/published/archived）
- `config`: 工作流配置（JSONB，包含节点、连接等信息）
- `is_template`: 是否为模板
- `template_id`: 如果从模板创建，记录模板ID
- `created_at`: 创建时间
- `updated_at`: 更新时间

**config JSONB结构示例**:
```json
{
  "nodes": [
    {
      "id": "node1",
      "type": "crawler",
      "position": {"x": 100, "y": 100},
      "data": {...}
    }
  ],
  "edges": [
    {
      "id": "edge1",
      "source": "node1",
      "target": "node2"
    }
  ]
}
```

### 2.3 工作流节点表 (workflow_nodes)

```sql
CREATE TABLE workflow_nodes (
    id BIGSERIAL PRIMARY KEY,
    workflow_id BIGINT NOT NULL REFERENCES workflows(id) ON DELETE CASCADE,
    node_id VARCHAR(100) NOT NULL,
    node_type VARCHAR(50) NOT NULL,
    position JSONB NOT NULL DEFAULT '{"x": 0, "y": 0}',
    config JSONB NOT NULL DEFAULT '{}',
    connections JSONB NOT NULL DEFAULT '[]',
    sort_order INTEGER NOT NULL DEFAULT 0,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    UNIQUE(workflow_id, node_id)
);

CREATE INDEX idx_workflow_nodes_workflow_id ON workflow_nodes(workflow_id);
CREATE INDEX idx_workflow_nodes_node_type ON workflow_nodes(node_type);
CREATE INDEX idx_workflow_nodes_config ON workflow_nodes USING GIN(config);
```

**字段说明**:
- `id`: 主键
- `workflow_id`: 工作流ID（外键）
- `node_id`: 节点唯一标识（在工作流内唯一）
- `node_type`: 节点类型（crawler/ai/output/condition等）
- `position`: 节点位置 {x, y}
- `config`: 节点配置（JSONB）
- `connections`: 连接关系数组（JSONB）
- `sort_order`: 排序顺序
- `created_at`: 创建时间
- `updated_at`: 更新时间

### 2.4 节点类型表 (node_types)

```sql
CREATE TABLE node_types (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL UNIQUE,
    category VARCHAR(50) NOT NULL CHECK (category IN ('crawler', 'ai', 'output', 'condition', 'transform', 'start', 'end')),
    icon VARCHAR(100),

    config_schema JSONB NOT NULL DEFAULT '{}',
    description TEXT,
    is_system BOOLEAN NOT NULL DEFAULT FALSE,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_node_types_category ON node_types(category);
CREATE INDEX idx_node_types_is_active ON node_types(is_active);
```

**字段说明**:
- `id`: 主键
- `name`: 节点类型名称（唯一）
- `category`: 分类（crawler/ai/output/condition/transform/start/end）
- `icon`: 图标名称或URL
- `color`: 节点颜色
- `config_schema`: 配置Schema（JSON Schema格式，用于动态生成表单）
- `description`: 描述
- `is_system`: 是否为系统内置节点
- `is_active`: 是否启用
- `created_at`: 创建时间
- `updated_at`: 更新时间

### 2.5 爬虫规则表 (crawler_rules)

```sql
CREATE TABLE crawler_rules (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(200) NOT NULL,
    description TEXT,
    url_pattern VARCHAR(500),
    method VARCHAR(10) NOT NULL DEFAULT 'GET' CHECK (method IN ('GET', 'POST', 'PUT', 'DELETE')),
    headers JSONB NOT NULL DEFAULT '{}',
    params JSONB NOT NULL DEFAULT '{}',
    selectors JSONB NOT NULL DEFAULT '{}',
    proxy_config JSONB,
    timeout INTEGER NOT NULL DEFAULT 30,
    retry_count INTEGER NOT NULL DEFAULT 3,
    user_agent VARCHAR(255),
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    created_by BIGINT REFERENCES users(id) ON DELETE SET NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_crawler_rules_name ON crawler_rules(name);
CREATE INDEX idx_crawler_rules_is_active ON crawler_rules(is_active);
CREATE INDEX idx_crawler_rules_created_by ON crawler_rules(created_by);
```

**字段说明**:
- `id`: 主键
- `name`: 规则名称
- `description`: 描述
- `url_pattern`: URL匹配模式（支持正则）
- `method`: HTTP方法
- `headers`: 请求头（JSONB）
- `params`: 请求参数（JSONB）
- `selectors`: 选择器配置（JSONB，包含CSS选择器、XPath等）
- `proxy_config`: 代理配置（JSONB）
- `timeout`: 超时时间（秒）
- `retry_count`: 重试次数
- `user_agent`: User-Agent
- `is_active`: 是否启用
- `created_by`: 创建者ID
- `created_at`: 创建时间
- `updated_at`: 更新时间

### 2.6 AI模型配置表 (ai_models)

```sql
CREATE TABLE ai_models (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL UNIQUE,
    provider VARCHAR(50) NOT NULL CHECK (provider IN ('openai', 'azure', 'anthropic', 'custom')),
    model_name VARCHAR(100) NOT NULL,
    api_key_encrypted TEXT NOT NULL,
    endpoint VARCHAR(500),
    params JSONB NOT NULL DEFAULT '{}',
    status VARCHAR(20) NOT NULL DEFAULT 'active' CHECK (status IN ('active', 'inactive', 'error')),
    max_tokens INTEGER DEFAULT 2000,
    temperature DECIMAL(3,2) DEFAULT 0.7,
    created_by BIGINT REFERENCES users(id) ON DELETE SET NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_ai_models_provider ON ai_models(provider);
CREATE INDEX idx_ai_models_status ON ai_models(status);
```

**字段说明**:
- `id`: 主键
- `name`: 模型配置名称（唯一）
- `provider`: 提供商（openai/azure/anthropic/custom）
- `model_name`: 模型名称（如gpt-4, gpt-3.5-turbo）
- `api_key_encrypted`: API密钥（加密存储）
- `endpoint`: API端点URL
- `params`: 模型参数（JSONB，如temperature, max_tokens等）
- `status`: 状态（active/inactive/error）
- `max_tokens`: 最大token数
- `temperature`: 温度参数
- `created_by`: 创建者ID
- `created_at`: 创建时间
- `updated_at`: 更新时间

### 2.7 任务表 (tasks)

```sql
CREATE TABLE tasks (
    id BIGSERIAL PRIMARY KEY,
    workflow_id BIGINT NOT NULL REFERENCES workflows(id) ON DELETE CASCADE,
    user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name VARCHAR(200),
    status VARCHAR(20) NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'running', 'completed', 'failed', 'cancelled')),
    progress INTEGER NOT NULL DEFAULT 0 CHECK (progress >= 0 AND progress <= 100),
    input_data JSONB,
    result JSONB,
    error_message TEXT,
    started_at TIMESTAMP,
    completed_at TIMESTAMP,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_tasks_workflow_id ON tasks(workflow_id);
CREATE INDEX idx_tasks_user_id ON tasks(user_id);
CREATE INDEX idx_tasks_status ON tasks(status);
CREATE INDEX idx_tasks_created_at ON tasks(created_at);
CREATE INDEX idx_tasks_result ON tasks USING GIN(result);
```

**字段说明**:
- `id`: 主键
- `workflow_id`: 工作流ID（外键）
- `user_id`: 用户ID（外键）
- `name`: 任务名称
- `status`: 状态（pending/running/completed/failed/cancelled）
- `progress`: 执行进度（0-100）
- `input_data`: 输入数据（JSONB）
- `result`: 执行结果（JSONB）
- `error_message`: 错误信息
- `started_at`: 开始时间
- `completed_at`: 完成时间
- `created_at`: 创建时间
- `updated_at`: 更新时间

## 四、索引优化建议

1. **主键索引**: 所有表的主键自动创建
2. **外键索引**: 所有外键字段都创建了索引
3. **查询索引**: 根据常用查询条件创建索引（status, created_at等）
4. **JSONB索引**: 对频繁查询的JSONB字段使用GIN索引

## 五、数据迁移策略

使用GORM的AutoMigrate功能，在应用启动时自动检查并创建/更新表结构。

**优点**:
- 简单易用，无需手动管理SQL脚本
- 自动处理字段添加、删除、修改
- 适合快速开发和迭代

**注意事项**:
- 生产环境建议使用专门的迁移工具（如golang-migrate）
- AutoMigrate不会删除未使用的字段，需要手动处理
- 重要数据变更建议先备份
